# わが家のご飯帖: 将来、企業に売る（譲渡する）ときのための準備

作成日: 2026年10月22日。アプリが成功して、企業から「アプリの権利を買いたい」と言われたときに、**高く・早く・揉めずに**渡せるようにするための準備です。今からやっておくこと、話が来たらやること、渡すときにやることの3段階に分けています。

> この文書は一般的な情報の整理です。売買の契約・税金・商標の出願の最終判断は、弁護士・弁理士・税理士に確認してください。金額と手続は変わるので、実行する前に出典の公式ページを見てください。

---

## 0. 結論（先にやっておく5つ）

1. **商標「わが家のご飯帖」「ご飯帖」「Gohancho」を出願する**（日本・第9類と第42類。海外で売れてきたらマドリッド協定議定書で国際登録）。名前は、売るときに一番値段がつく資産です。
2. **権利を1人（または自分の会社）にまとめる**。Apple Developer・GitHub・RevenueCat・ドメイン・メールを、個人の生活用のアカウントから分けて「アプリ用」にする。
3. **自分で作った証拠を残す**。開発の履歴（`ios-app/権利の記録/開発履歴.csv`）と、ファイルの指紋（`ファイルの指紋.txt`）に**確定日付やタイムスタンプ**を付ける。詳しくは `独自性の記録.md`。
4. **外から借りている部品を一覧にし、売れない部品を減らす**（下の表 3）。特に音声（VOICEVOX）と、使っていない Wikipedia 写真の処理は整理しておく。
5. **数字を毎月残す**。ダウンロード数・有料会員数・解約率・売上（App Store Connect と RevenueCat の画面）。買う側は数字で値段を決めます。

## 1. 何を売るのか（譲渡の対象）

| 問い合わせの窓口・お客様の声の記録 | `SUPPORT_EMAIL`、GitHub Issue | メールアドレスの移管か転送 |

### 2-2. 権利を1か所にまとめる

- **個人のままか、会社にするか**: 個人のままでも売れますが、売上が大きくなったら法人（合同会社など）にして、アプリの権利を会社に移しておくと「会社ごと売る」「アプリだけ売る」の両方を選べます。税金の差は大きいので税理士に相談（**わかりません**）。
- **アカウントを分ける**: Apple Developer・RevenueCat・GitHub・サポート用メール・ドメインを、ご飯帖専用にする。いまのリポジトリには栽培管理・在庫・株の自動売買など**ほかのアプリも同じ場所にある**ので、そのまま渡すと見せたくないものまで渡ります。
- **パスワードと2段階認証の回復手段を、自分の手元に**（家族や外注先の電話番号に紐づけない）。

### 2-3. 「自分で作った」証拠を残す

- `ios-app/権利の記録/開発履歴.csv`: 2026年9月29日の最初の版からの、すべての変更（日時・内容）。GitHub にも同じ履歴が残っています。
- `ios-app/権利の記録/ファイルの指紋.txt`: アプリ本体・レシピ・翻訳・絵の部品の SHA-256（ファイルの指紋）。
- これに**日付の証明**を付ける方法（どれか1つで十分）:
  1. 公証役場の「確定日付」（印刷した一覧に付けてもらう。手数料は少額。**金額は出典不明**のため公証役場で確認）
  2. 民間のタイムスタンプサービス（電子ファイルに日時を付ける）
  3. 最低限: GitHub に push 済み（履歴は GitHub 側にも日時つきで残る）
- 大きな変更（バージョンを出すたび）に指紋を作り直すと、成長の記録になります（Claude に「権利の記録を更新して」と頼めば作ります）。

### 2-4. AI（Claude・ChatGPT）で作った部分の扱いを明らかにしておく

このアプリのコード・文章・絵の多くは、あなたの指示で Claude（Anthropic）が作り、あなたが確認・修正して完成させています。売るときに必ず聞かれる点です。

| 論点 | いまの整理 |
| --- | --- |
| AI の会社との関係 | Anthropic の利用規約では、規約を守っている限り、出力に関して Anthropic が持つ権利（もしあれば）を利用者に譲ると書かれています。**AI の会社が権利を主張する心配は小さい** |
| 著作権があるか | 日本では、文化庁の「AIと著作権に関する考え方について」（2024年）で、AI が作っただけのものは著作物にならないことがあり、人が具体的に指示した・選んだ・直した部分は認められうる、と整理されています。**どこまで認められるかは個別の判断で、わかりません** |
| だから何をするか | ① あなたが決めたこと（名前・価格・お膳の見せ方・国の選び方・直させた点）が会話と履歴に残っていることを示せるようにする。② 売る契約では「著作権がある部分は譲渡する」に加えて、**商標・ノウハウ・アカウント・利用者・データの一式**を対象にする（著作権に頼りすぎない）。③ 買い手には AI を使ったことを正直に伝える（隠すと後で契約違反になりうる） |
| ChatGPT の絵 | いま同梱している絵 464枚は**すべて SVG の手描き部品（`tools/illustrations/draw/`）で作ったもの**で、ChatGPT の画像は入っていません（`img/dish/manifest.json` の via がすべて svg）。ChatGPT の取りこみ手順（`tools/illustrations/prompts.md`）は残っていますが、使っていません |

出典: 文化庁「AIと著作権に関する考え方について」（2024年3月） https://www.bunka.go.jp/seisaku/chosakuken/aiandcopyright.html ／ Anthropic Consumer Terms of Service（Rights to Materials） https://www.anthropic.com/legal/consumer-terms

### 2-5. 数字を残す（値段の根拠）

毎月1回、次をスクリーンショットか CSV で `ios-app/権利の記録/月次/` に残す（Claude に頼めば表にします）。

- App Store Connect: ダウンロード数、国別、お試し開始数、有料への転換率、解約率、売上、評価
- RevenueCat: MRR（毎月の売上）、有料会員数、解約率、LTV
- かかった費用: Apple Developer の年会費、GitHub Actions、ドメイン、外注費

小さなアプリの売買は、一般に「1年間の利益の何倍か」で値段が話されます。倍率は相場で変わるので、ここでは書きません（**出典不明**）。

## 4. 売る話が来たらやること

### 4-1. ご飯帖だけのリポジトリに分ける

`gohancho/`・`ios-app/`・`tools/illustrations/`・`tools/i18n/`・`.github/workflows/ios-release.yml`・`.github/ISSUE_TEMPLATE/gohancho-*.yml`・`.claude/agents/`（サポートチーム）だけを、履歴つきで新しいリポジトリに切り出します（`git filter-repo` などで可能。Claude に頼めます）。ほかのアプリ（栽培・在庫・株）を見せずに済みます。

### 4-2. 公開ページを自分のドメインへ

プライバシーポリシー・サポートのページが `github.io/toresabi/...` のままだと、リポジトリを渡すときに URL が変わり、App Store の登録も直す必要が出ます。`gohancho.app` のような独自ドメインに移しておくと、ドメインごと渡せます（ドメインが空いているかは**わかりません**）。

### 4-3. 秘密保持契約（NDA）を先に結ぶ

数字やソースコードを見せる前に NDA を結ぶ。見せる順番は「公開されている数字 → 月次の数字 → ソースコード」。

### 4-4. 買い手が調べること（デューデリジェンス）に答えられる資料

| 聞かれること | 用意するもの |
| --- | --- |
| 誰が作ったか・権利は誰にあるか | `独自性の記録.md`、開発履歴、確定日付つきの指紋、AI 利用の説明（2-4） |
| 他人の権利を侵していないか | 上の部品一覧（3）、`類似アプリの調査と差別化.md`、商標の調査結果 |
| 売上は本物か | App Store Connect・RevenueCat の画面、入金の記録 |
| 利用者の個人情報は | プライバシーポリシー（アカウント不要・データは端末内・購入履歴と RevenueCat の ID だけ） |
| 揉めごとはないか | Apple の審査の履歴、返金の件数、お客様の声の記録（`サポート体制.md`） |
| 動かし続けられるか | 申請ガイド・アップデートの手順・GitHub Actions・サポートチームの手順（そのまま引き継げる） |

## 5. 渡すときにやること（契約と移管の順番）

1. **契約書**（弁護士に作ってもらう）に入れる点:
   - 譲渡の対象を一つずつ書く（上の表 1 の全部）
   - 著作権は「著作権法第27条・第28条の権利を含む」と**はっきり書く**（書かないと翻案権などが売り手に残ったと推定される＝著作権法61条2項）
   - 著作者人格権は譲渡できないので「行使しない」と約束する
   - 商標は移転登録の手続きをどちらがするか
   - 移管の期間中のサポート（例: 1〜3か月の引き継ぎ）、表明保証（他人の権利を侵していない等）、競業避止（似たアプリを作らない期間）
   - 代金の払い方（一括・分割・売上連動）
2. **Apple の App 譲渡**:
   - 条件: 少なくとも1つのバージョンが公開済み、両方のアカウントが最新の契約に同意済み、**アプリ内課金の商品 ID が買い手のアカウントの ID と重ならない**、など
   - 自動更新のサブスクリプションがあるので、**譲渡の前に App 固有の共有シークレットを作って買い手に渡す**（買い手はそれで会員の確認を続ける）。譲渡後に新しいシークレットを作り直す
   - 開始はアカウント所有者（Account Holder）だけができ、相手が60日以内に受けないと失効
   - 譲渡するとアプリは自分のアカウントから消えるので、**情報を先にバックアップ**
3. **RevenueCat**: 買い手のアカウントで有料 App 契約が有効か確認 → 買い手の App Store の認証情報で RevenueCat を設定し直し → Sandbox で購入テストをしてから譲渡を開始
4. **商標**: 特許庁に移転登録を申請
5. **GitHub**: 分けたリポジトリを買い手の組織に移す（Settings → Transfer）。Secrets は移らないので、買い手が登録し直す
6. **remote.json の置き場所**: アプリは起動時に GitHub の決まった場所の `remote.json` を読みます（`gohancho/index.html`）。リポジトリが移ると読み先が変わるので、**譲渡の前の版で読み先を買い手の場所に変えたアップデートを出しておく**か、独自ドメインに置いておく

出典: Apple「App 譲渡の概要」 https://developer.apple.com/help/app-store-connect/transfer-an-app/overview-of-app-transfer/ ／ Apple「App 譲渡の条件」 https://developer.apple.com/help/app-store-connect/transfer-an-app/app-transfer-criteria/ ／ RevenueCat「Update after developer account transfer」 https://www.revenuecat.com/docs/revenuecat-support/common-tickets/update-after-developer-account-transfer ／ 著作権法第61条2項の解説（文化審議会資料） https://www.mext.go.jp/b_menu/shingi/bunka/gijiroku/013/05072901/003-6.htm

## 7. 自己検算と注意

- 特許庁の料金は 2023〜2025 年の資料で確認した額です。2026年の料金表は確認できていません。出願の前に最新の料金一覧を見てください。
- Apple の譲渡の条件は Apple のヘルプ（2026年10月の検索時点）によります。古い第三者の解説には「自動更新のサブスクがあると譲渡できない」とあるものがありますが、Apple の現行のヘルプでは共有シークレットを使えば譲渡できる扱いです。実行するときは App Store Connect の「App を譲渡」に出る条件を正としてください。
- AI で作ったものの著作権の範囲は、法律の解釈が固まっていません（**わかりません**）。そのため、著作権だけに頼らず、商標・アカウント・利用者・数字を一式で渡す形にするのが安全です。
