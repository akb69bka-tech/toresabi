# ご飯帖 サポート体制（3チーム）と相談窓口

作成日: 2026年10月21日。公開後に「お客様の声」「不具合」「Apple とのやりとり」が来たとき、**どこに書けば、誰（どの Claude 担当）が、何をするか**を1枚にまとめたものです。担当はすべて Claude のエージェント（`.claude/agents/`）で、あなたは「書く・マージを押す・審査へ提出を押す」だけです。

---

## 1. 相談する場所（ここに書けば動きます）

| 相談したいこと | 書く場所 | 呼び出し方 |
| --- | --- | --- |
| **なんでも相談・困った**（まずここ） | GitHub Issue 「【ご飯帖 サポート窓口】」（常設の Issue。コメントで書く） | Claude に「/support #<Issue番号>」または本文を貼る |
| 不具合の報告（利用者から・自分で見つけた） | GitHub → Issues → New issue → **「ご飯帖の不具合・要望」** フォーム | 同上 |
| 課金・返金・復元できない | New issue → **「ご飯帖の課金・返金の相談」** フォーム | 同上 |
| 相談・質問・値段や方針の悩み | New issue → **「ご飯帖の相談・質問」** フォーム | 同上 |
| 利用者から見た連絡先 | アプリの「設定 → ご意見・不具合を送る」（`SUPPORT_EMAIL` 宛てメール）、`gohancho/support.html` | 届いたメール本文を Claude に貼る |
| Apple からの連絡（審査の差し戻し） | App Store Connect の Resolution Center の文をそのまま Issue または Claude に貼る | 「/support」＋本文 |

Claude Code のチャットで `/support` と打つと `.claude/skills/support/SKILL.md` の手順で窓口担当が受け、担当チームに振り分けます。

---

## 2. 3つのチームと担当

### チームA: お客様の声を反映するチーム
| 担当（エージェント） | 役目 |
| --- | --- |
| `support-desk` | 受付。声を整理し、緊急度を決め、担当に渡す |
| `voice-of-customer` | レビュー・メール・Issue の要望を集めて分類・集計し、次のバージョンに入れる改善を優先順に提案。小さい改善は PR まで |
| `app-fixer` | 改善の実装（文言・並び・既定値・レシピの追加など） |

集める入口: App Store Connect「評価とレビュー」、`SUPPORT_EMAIL` のメール、Issue、家族の感想。頼み方: 「レビューをまとめて次に入れる改善を出して」「この要望を入れて」。

### チームB: 不具合解消チーム
| 担当 | 役目 |
| --- | --- |
| `support-desk` | 受付・再現の確認・緊急度 |
| `app-fixer` | アプリ本体の修正・テスト・翻訳辞書チェック・PR |
| `billing-support` | 課金に関わる不具合（購入・復元・表示）、お知らせ（`remote.json`）案 |
| `release-manager` | 修正版のバージョン上げ・GitHub Actions の起動・優先審査の文面 |

頼み方: 「献立が出ない不具合。直して」「購入したのに使えないと言われた」「1.1.1 で申請して」。

### チームC: Apple との窓口対応チーム
| 担当 | 役目 |
| --- | --- |
| `release-manager` | 申請・アップロード・「審査へ提出」の案内・Expedited Review（優先審査）の申請文 |
| `review-responder` | 差し戻しの読み解き（ガイドライン条項の特定）・直す/説明する判断・Resolution Center への返信文（英語） |
| `billing-support` | 返金・解約・サブスクリプションの規約まわり（Apple が決めることと、こちらでできることの線引き） |

頼み方: 「Apple からこの文で差し戻された（本文貼り付け）」「返金を求められた」「優先審査を申請したい」。

## 3. 緊急度と対応の目安

| 緊急度 | 例 | 最初の30分でやること | 目標 |
| --- | --- | --- | --- |
| 🔴 緊急 | 起動しない／課金したのに使えない／データが消える／個人情報 | `remote.json` の `notice` でお知らせ（審査なし・次の起動から表示）→ チームB が修正 → 優先審査 | お知らせ: 当日。修正版: 1〜3日 |
| 🟠 高 | 献立・レシピ・買い物メモが使えない | 再現 → 修正 → 通常の申請 | 1週間 |
| 🟡 中 | 表示崩れ・翻訳・レシピの誤り | Issue にためて、次の更新にまとめる | 次の更新 |
| 🟢 低 | 要望 | チームA が月1で集計・提案 | 月1 |

> 審査にかかる日数は Apple 次第で保証できません（出典不明）。

## 4. 利用者への返事の文例（コピーして使う）

**不具合のお詫び（日本語）**
> ご不便をおかけして申し訳ありません。「◯◯」の不具合を確認し、修正版を準備しています。公開されましたらアプリの更新をお願いします。お急ぎのところ恐れ入りますが、今しばらくお待ちください。

**Bug acknowledgement (English)**
> We're sorry for the trouble. We've confirmed the issue with "◯◯" and a fix is on its way. Please update the app once the new version is available. Thank you for your patience.

**購入したのに使えない**
> お手数ですが、アプリの「設定 → 購入を復元」をお試しください。それでも使えない場合は、設定の一番下に表示される番号（サポート用の番号）をお知らせください。こちらで購入の状態を確認します。

**返金を求められた（返金は Apple が行います。自分で約束しない）**
> サブスクリプションの返金は Apple が取り扱っています。お手数ですが https://reportaproblem.apple.com/ から「問題を報告」で申請してください。解約は iPhone の「設定 → 自分の名前 → サブスクリプション」からできます。

**Refund request (English)**
> Refunds for subscriptions are handled by Apple. Please request one at https://reportaproblem.apple.com/. You can cancel anytime in Settings → your name → Subscriptions.

**App Store レビューへの返信（150字以内）**
> ご意見ありがとうございます。「◯◯」は次の更新で対応予定です。今後もよりよいアプリにしていきます。

## 5. `remote.json` のお知らせ例（審査なしで全端末に出ます）

`gohancho/remote.json`（main ブランチ）を直して main に入れると、次の起動から表示されます。`id` を変えると、閉じた人にもまた出ます。

```json
{
  "version": 1,
  "notice": {
    "id": "2026-11-01-shopping",
    "ja": "買い物メモが消える不具合を確認しています。修正版（1.1.1）を準備中です。ご迷惑をおかけして申し訳ありません。",
    "en": "We're aware of an issue where the shopping list disappears. A fix (1.1.1) is on the way. Sorry for the trouble."
  },
  "plan": {},
  "minVersion": ""
}
```

全員にいったん無料で開けたいとき（課金の障害が長引くとき）: `"plan": {"billingMode": "free"}` 。元に戻すときは `{}` に。

## 6. 自己検算と注意
- エージェントは `.claude/agents/*.md`、窓口の手順は `.claude/skills/support/SKILL.md`。Claude Code で開いたときにだけ使えます（GitHub の Issue に書いただけでは、Claude に「/support #番号」と頼むまで動きません。自動で動かしたい場合は定期タスクを設定できます。希望があれば設定します）。
- Secrets（Apple の鍵）が GitHub に登録されるまで、修正版の自動アップロードは動きません。
- 返金・解約・審査日数は Apple が決めるため、文例に日付や金額の約束を入れないでください。法律面は専門家に確認を（**わかりません**）。
